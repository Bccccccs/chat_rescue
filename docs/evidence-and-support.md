# 实测证据与支持边界

当前 0.3.5 为 experimental，提供 Mac 命令行与原生桌面向导。当前实测环境是 macOS 27.0、Apple Silicon、微信 4.1.13；Python 3.14，SQLCipher 通过 Homebrew 安装。环境通过检查不等于所有微信版本或所有消息类型均可恢复。

## 证据分层

| 证据 | 已观察到的结果 | 不能据此宣称 |
| --- | --- | --- |
| 模拟文本、本地系统实验 | 电脑显示，`server_id=0` 时手机缺失；修改发送者映射后仍缺失 | 电脑可见即可保证手机恢复 |
| 模拟消息的非零实验编号 | 手机出现，但方向反了 | 可以为真实记录虚构编号 |
| 模拟消息补充对方 packed 短元数据 | 用户确认手机按对方侧显示 | 所有类型、所有版本都可迁移 |
| 真实跨账号两条消息：名片、文件消息条目 | 视角翻转后用户确认恢复成功，数据库字节比对通过 | 附件内容已补齐，或已完成完整手机跨账号实机验证 |
| 该真实案例的手机再次导出 | 没有独立截图或明确的逐项验收 | 已独立验证手机内容、方向与完整性 |

用户确认、数据库比对与独立手机分项验收属于不同证据。公开仓库不包含这些私人聊天、密钥或截图；也不包含伪造实验编号的工具。

## 0.3.5 桌面证据

- 本机 61 项合成测试通过，覆盖双向补齐、变化拒绝、部分失败回执和撤回保护。
- 桌面应用构建与本地代码签名校验通过；打包目标 macOS 14+ 不等于最低版本已经实机验证。
- 页面截图展示准备、登录、读取、预览与结果检查页面；结果检查页面是操作指引，不是数据库已应用的回执。
- 真实双账号桌面应用、微信显示与手机迁移仍需分别验收。此前单向案例不能代替本版双向验收。

## 首版范围

- 仅一个 `message_0.db` 消息分片；发现 `message_1.db` 等额外分片时拒绝。不得删除其他分片来绕过检查。
- 双方授权的单聊 bundle，从保留方 B 向误删方 A 恢复文本（类型 1）、名片（42）、文件消息（49 的子类型 6）条目。会话内出现其他类型时整段拒绝，不自动过滤跳过。
- 复制与重签专用取钥副本；保留原版微信。
- 密钥匹配、明文副本导出、参与者映射、恢复预览、去重、冲突拒绝和应用前校验。
- 本地三库候选与协调应用，保留原件，部分失败尝试回撤。

真实 `server_id` 必须来自源记录。手机号、微信号与真实账号身份不因视角改变；只调整本地映射和发送/接收方向。

## 不宣称覆盖的范围

群聊、附件内容补齐、撤回语义、所有特殊消息类型、其他平台与任意微信版本，不在首版覆盖承诺内。具体消息是否可恢复，以当前工具预览与校验结果为准。名片或文件消息条目恢复，不等于附件资源完整可打开。

项目不自动发送消息，不执行云端恢复，也不保证微信服务器或手机自动接受本地修改。电脑端验收与手机端手动迁移验收应分别进行；未验证的结果应标为未验证。

不要为恢复再次删除任何记录。群聊等不支持范围的说明不是要求用户删掉这些资料。
