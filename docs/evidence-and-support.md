# 实测证据与支持边界

本地开发版0.5.0提供可选Mac原语音和图片、视频、文件附件实验模式，新增文件规则见[附件实验说明](attachment-recovery.md)和[语音说明](voice-recovery.md)。已发布0.3.7下载包不包含这些改动；实际打开/播放和手机迁移尚未验收。下面未注明媒体的步骤仍指基础模式。

当前 0.3.5 为 experimental，提供 Mac 命令行与原生桌面向导。当前实测环境是 macOS 27.0、Apple Silicon、微信 4.1.13；Python 3.14，SQLCipher 通过 Homebrew 安装。环境通过检查不等于所有微信版本或所有消息类型均可恢复。

## 证据分层

| 证据 | 已观察到的结果 | 不能据此宣称 |
| --- | --- | --- |
| 模拟文本、本地系统实验 | 电脑显示，`server_id=0` 时手机缺失；修改发送者映射后仍缺失 | 电脑可见即可保证手机恢复 |
| 模拟消息的非零实验编号 | 手机出现，但方向反了 | 可以为真实记录虚构编号 |
| 模拟消息补充对方 packed 短元数据 | 用户确认手机按对方侧显示 | 所有类型、所有版本都可迁移 |
| 真实跨账号两条消息：名片、文件消息条目 | 视角翻转后用户确认恢复成功，数据库字节比对通过 | 附件内容已补齐，或已完成完整手机跨账号实机验证 |
| 该真实案例的手机再次导出 | 没有独立截图或明确的逐项验收 | 已独立验证手机内容、方向与完整性 |

用户确认、数据库比对与独立手机分项验收属于不同证据。公开仓库不包含这些私人聊天、密钥或截图；也不包含伪造实验编号的工具。

## 0.3.5 桌面证据

- 本机 61 项合成测试通过，覆盖双向补齐、变化拒绝、部分失败回执和撤回保护。
- 桌面应用构建与本地代码签名校验通过；打包目标 macOS 14+ 不等于最低版本已经实机验证。
- 页面截图展示准备、登录、读取、预览与结果检查页面；结果检查页面是操作指引，不是数据库已应用的回执。
- 真实双账号桌面应用、微信显示与手机迁移仍需分别验收。此前单向案例不能代替本版双向验收。

## 首版范围

- 首版仅一个 `message_0.db` 消息分片；源码后续新增全部现有编号分片的恢复支持，证据见文末，不回溯修改首版实机结论。不得删除其他分片来绕过检查。
- 双方授权的单聊 bundle，从保留方 B 向误删方 A 恢复文本（类型 1）、名片（42）、文件消息（49 的子类型 6）条目。会话内出现其他类型时整段拒绝，不自动过滤跳过。
- 复制与重签专用取钥副本；保留原版微信。
- 密钥匹配、明文副本导出、参与者映射、恢复预览、去重、冲突拒绝和应用前校验。
- 本地三库候选与协调应用，保留原件，部分失败尝试回撤。

真实 `server_id` 必须来自源记录。手机号、微信号与真实账号身份不因视角改变；只调整本地映射和发送/接收方向。

## 不宣称覆盖的范围

群聊、附件内容补齐、撤回语义、所有特殊消息类型、其他平台与任意微信版本，不在首版覆盖承诺内。具体消息是否可恢复，以当前工具预览与校验结果为准。名片或文件消息条目恢复，不等于附件资源完整可打开。

项目不自动发送消息，不执行云端恢复，也不保证微信服务器或手机自动接受本地修改。电脑端验收与手机端手动迁移验收应分别进行；未验证的结果应标为未验证。

不要为恢复再次删除任何记录。群聊等不支持范围的说明不是要求用户删掉这些资料。

## Windows 开发支持补充

新增 Windows CLI 离线适配，复用已有密钥、SQLCipher 4 与兼容四库引擎。新增面向 4.2.0.x x64 的实验取钥命令，以明确 PID、程序签名/版本/路径、当前用户及四库验证约束范围。Windows 本机合成验证、真实取钥和真实客户端显示属于不同证据；[Windows 桌面向导](windows-desktop.md) 已本机编译和检查界面，尚未完成真实 GUI 应用验收。详见 [Windows 说明](windows.md)。

## 2026-11-03 Windows 4.2.0.12 实机与隔离试验

- 两个本人登录的账号分别只读取钥成功，各自四库首页 HMAC 与全库完整性通过；正常退出后再次验证四库，导出及 DB/WAL/SHM 快照成功。签名检查实际使用系统 Windows PowerShell Security 模块，避免宿主模块路径影响。
- 观察到与当前引擎一致的消息、资源和会话表结构；完全空白的目标 message_0.db 尚无 Name2Id。使用该空白库的加密副本生成计划时，以 `no such table: Name2Id` 拒绝，未应用。该初始化场景尚未适配，不能声称空白账号可直接恢复。
- 在额外隔离的测试副本中，显式初始化测试 Name2Id，添加三条带测试标记的合成文本，使用合成测试编号；未向微信发送消息，未将合成数据应用到真实账号。视角转换、加密候选、实验副本应用、再次解密比对通过；重复计划新增 0、去重 3。
- 比对两个真实账号的四库与所有 DB/WAL/SHM 清单，原件哈希未改变；已导出的明文原件也未编辑。密钥、数据库、身份与私有报告均留在本机，不提交仓库。
- 尚未验收真实 Windows 库应用、微信界面显示或独立手机迁移；显式初始化后的合成副本不能替代原始空白库的直接恢复验证。

## Windows 五步向导开发验证

后续本机配对观察：同一真实文本在发送侧 packed 字段 2 为 3、status=2，接收侧为 2、status=3；接收侧还含字段 11，转换保留该字段。两端正文、类型、发送者和真实编号一致，本地时间差一秒且 sort_seq 差 1000。按独立配置处理后，新生成双向预览两端各新增 0、去重 1，保留各自原记录。该证据只支持 4.2.0.12 文本，不能外推名片、文件或其他完整版本。

新的三条合成文本候选在源账号副本中准备完成，再通过 bundle 恢复到目标副本：新增 3、保留已有去重 1，目标为两收一发；加密再解密比对通过，重复恢复新增 0、去重 4。此处记录的是候选与副本验证，尚未应用真实库或验收客户端。旧的 legacy 方向实验候选已标记为不应应用，保留现场。

随后由用户明确确认三条本地实验文本，仅应用到源账号：成功回执为 `applied`，再次从实际源库快照导出，核对编号、身份、方向、status、正文与时间一致；原有会话和联系人保留，目标账号的 DB/WAL/SHM 哈希未变。新生成实际双向预览为目标新增 3、去重 1，源新增 0、去重 1，目标尚未应用。三条文本均标记“本地实验、非真实发送”；该实验没有证明真实聊天跨账号恢复、微信客户端显示或手机迁移。首次应用前曾因只读核验更新 SHM 而被哈希检查拒绝，未开始替换；保留旧现场后，从当前快照重建内容、时间与实验编号完全相同的新候选，再按已有具体确认应用。

首次使用测试采用新的私有工作目录，确认账号设置为空、无旧昵称和密钥预填、无历史任务，原工作目录保持不变。移除全局扫描旧实验回执补全昵称的行为。用户已自行完成准备并进入顺序登录页面，后续完整人工验收仍在进行。

## 2026-11-04 多分片与 Windows 类型结构转换

源码新增现有编号消息分片的全链路清单：逐库身份解析、跨分片去重/碰撞拒绝、密钥覆盖、加密导出、候选及 DB/WAL/SHM 备份、应用中断回撤、双向补齐及完整撤回。使用临时合成账号与随机 SQLCipher 密钥验证，不是多分片真实账号恢复或客户端验收。不会自动创建新分片。

Windows 新 `windows-4.2.0.12-structured` 配置对所有正 int64 消息类型转换可明确识别的 packed 发送者/方向字段；文本按已观察状态转换，非文本保留原 status/upload/download 状态，避免套用文本播放/下载语义。类型、原始内容及不透明字段保留，资源/会话引用重建；方向缺失、冲突、无真实正 server_id 仍拒绝。合成用例覆盖图片、语音、视频、表情、位置、名片与多种 49 子类型；不证明附件内容完整、非文本客户端显示或手机迁移。旧 text 配置仍限文本，Mac/legacy 类型范围不扩大。

参考远端 `f5153a1` 的 Mac 语音/附件实验模式：媒体本体与消息条目分开处理，不能把条目转换称为语音可播放或图片可打开；Windows 本次不套用 Mac 的媒体路径或 DAT 密钥。B 导入提醒移到 A 核验退出之后、B 登录并读取之前，并要求本人先确认电脑 B 中目标单聊完整；这项确认不表示工具已经验证导入结果。

本机 WPF 可执行文件构建通过，实际检查准备、登录、读取、无计划预览、隔离报告及未应用结果页面；环境与腾讯签名检查返回成功。隔离报告显示三条恢复与三条去重，并禁止转为真实应用。114 项合成测试中 104 项通过、10 项因 Mac 平台或符号链接权限跳过，其中桌面桥接保护测试 21 项均通过。界面开发期间没有启动微信、重新取钥或修改真实库；Windows GUI 真实应用、电脑显示和手机验收仍未完成。构建为依赖本机 Python / SQLCipher / 仓库的开发版，当时尚非独立安装包。0.3.6 后续增加内置运行时的安装器与便携包，已通过本机隔离安装、安装后GUI启动、卸载和用户资料保留检查；详见 Windows 部署说明。
