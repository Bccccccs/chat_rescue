# 公开测试

在仓库根目录安装 Python 3.14 和 SQLCipher 后运行：

```sh
python3.14 -W error::ResourceWarning -m unittest discover -s tests -v
```

所有账号、消息正文、消息编号和文件元数据来自代码生成的合成数据。测试在临时目录生成数据库和随机密钥，结束后自动清理，不打开或修改真实微信。加密集成测试会用本机 SQLCipher 库；没有库时这些测试会跳过，所以不能把跳过解释为通过验证。

测试覆盖：发送者与 packed 方向映射、真实编号保留与碰撞拒绝、去重、资源关联与会话索引、稀疏隐式 rowid、已提交 WAL 读出、原盐再加密、原库变更拒绝、候选变更拒绝、写入第二库失败时 DB/WAL 回撤，以及加密 B 库→CLI 单聊导出→A 候选→应用→重新解密比对。

核心合成恢复测试会替代微信进程检查；Windows 原生测试另行检查文件锁、ACL、进程清单解析与目录定位。不涵盖 LLDB 取钥、微信客户端显示或手机迁移，这些需按 SOP 在受支持环境人工验收。

GitHub Actions 的 macOS 任务安装 SQLCipher 后执行相同测试，先要求依赖存在以避免集成测试静默跳过；工作流使用 [setup-python](https://github.com/actions/setup-python) 安装指定 Python。仓库首次发布时，以本机测试回执为已知结果，远程 CI 结果应查看 Actions 的实际运行状态。

桌面顺序登录状态测试位于 `tests/test_login_flow.py`：有 Swift 编译器时编译运行实际 `desktop/LoginFlow.swift`，覆盖 A 未确认时禁止打开 B、未成功打开时不能确认、B 必须确认旧聊天、确认不跨阶段或会话复用。缺少 Swift 时该项跳过；构建脚本编译状态机和 SwiftUI 界面。

Windows CI 使用固定版本且校验下载哈希的 SQLCipher DLL，运行同一套合成测试及 Windows 原生测试。2026-11-03 本机 Windows x64、Python 3.14.10、SQLCipher 4.5.2 community：共 114 项，104 项通过、10 项跳过（9 项 Mac 专用测试，1 项缺少 Windows 符号链接权限；该项继续由 Mac CI 覆盖）。加密集成测试未跳过；包含中文路径的 B → bundle → A、双向去重、失败回撤、撤回变化保护。远程 Windows/Mac CI 尚未在本次本机修改中执行，不把工作流配置视为运行成功。

其中 Windows 实验取钥新增 12 项测试，使用合成 Config.Cipher 对象、随机密钥与构造的 HMAC 页面；Win32 内存读取只检查测试 Python 自身的合成缓冲区。覆盖跨块特征、四库覆盖、损坏/超时拒绝、完整性失败不保存、已有输出保护、异常释放句柄、进程路径不匹配及非 4.2.0 版本拒绝。未启动或扫描真实微信，不能据此宣称 4.2.0 实机取钥成功。

Windows 桌面桥接另有 21 项合成测试，覆盖应用确认与计划哈希、部分/中断/完成回执、撤回确认、电脑验收、账号进程歧义、空白库错误、隔离报告成功状态及密钥隔离、账号路径设置不保存密钥值。WPF 向导在本机实际编译并打开，准备页环境/签名检查、其余五步页面及前次隔离报告载入均已检查。该 UI 检查没有启动真实微信、重新取钥或应用真实库，不能代替实际 GUI 恢复验收。

新增 7 项独立方向配置测试：严格拒绝旧配置中的发送值 3、Windows 两方向与 status、未知 packed 字段保留、跨配置文本转换、重复去重、未验证类型/配置拒绝、取钥回执账号/目录/完整版本绑定。一秒本地时间差仅按明确条件去重，测试同时拒绝更大时间差、排序不对应和正文冲突。另有 2 项真实 .NET → Python 管道测试覆盖中文、表情、路径和默认 GBK 失败复现。

首次使用另增 3 项工作目录隔离测试，覆盖全新设置为空、原设置保持不变、相对工作路径拒绝，以及当前工作目录昵称与旧实验目录隔离。最终本机完整集114项，104通过、10跳过；Windows界面本次仅编译检查，不替用户继续实际恢复。

0.3.6 安装包新增3项输入测试，拒绝损坏依赖并只打包Git索引内允许的源码/文档/许可，生成相对运行时配置；真实.NET管道另增1项安装目录移动测试。安装包已在中文隔离目录实际安装、打开GUI，并卸载核对私有资料标记仍在。验证仅覆盖本机安装生命周期，不代替干净虚拟机或真实恢复验收。


## 2026-11-04 Windows 多分片与类型结构转换

在 `codex/multi-message-shards` 分支使用 Python 3.14.6、Windows x64 和 SQLCipher 4.5.2 community DLL 验证。DLL 沿用 CI 固定的 sqlitepclraw.lib.e_sqlcipher 2.1.11 包及 SHA256 校验。命令：

```powershell
$env:PYTHONUTF8 = '1'
$env:SQLCIPHER_LIBRARY = '<已核验的 SQLCipher DLL 绝对路径>'
python -W error::ResourceWarning -m unittest discover -s tests -v
```

最终 153 项：143 项通过，10 项因 Mac/Swift 平台条件跳过；SQLCipher 加密集成没有跳过。新增 `tests/test_shards.py` 与 `tests/test_windows_login_flow.py`：覆盖非连续编号/数字排序、非零分片会话、独立 Name2Id 与重复 local_id、跨分片等价消息去重/冲突、未知 Msg 表碰撞、全库原件清单、缺密钥拒绝、计划后新增分片/sidecar、路径越界/候选父目录符号链接拒绝、多个消息库及 WAL/SHM 失败回撤、双向应用与撤回精确还原。密钥验证允许读者自身刷新 SHM 索引，但不允许原 DB/WAL 或分片集合改变；应用仍严格核对全部 SHM 哈希。

新 Windows structured 配置合成测试覆盖 15 种类型/子类型、双方向及重复恢复，保留正文与不透明字段，非文本不套用文本 status；一秒时间差例外仅允许文本。没有真实 server_id、未知方向结构仍不支持。测试不导入或播放真实媒体，不能证明所有类型客户端兼容。

独立审查复现了撤回清单越界以及目标跨分片相同消息误判冲突，两项均以 RED→GREEN 回归修复。额外回归确认候选父目录符号链接不被接受。Windows 的 B 导入提醒/确认门槛通过实际 C# 状态机编译运行，以及 Python 桥接拒绝测试；完整 WPF 本机构建成功，本次没有打开微信或修改真实聊天库，未做真实 GUI 恢复/微信显示/手机迁移验收。

参考远端 `f5153a1` 的 Mac 媒体实现与 B 导入提示；本分支基于 `1215d16`，未合并 Mac 媒体模块。Windows 本次实现全类型消息条目的明确结构转换，不搬运语音/图片/视频/文件本体，不接受 Mac 媒体 v2/v3 bundle。
