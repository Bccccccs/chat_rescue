# Windows 账号发现与昵称提示：调查和实现边界

2026-11-09，纳入0.6.0的源码维护。仅静态阅读源码和合成测试，没有启动微信、读取真实聊天库或私有密钥，也没有读取真实登录缓存。

## 现有证据

| 来源 | 能支持什么 | 不能据此判断什么 |
| --- | --- | --- |
| `__main__.roots()` | 当前用户重定向文档位置和已配置基础目录中的 `db_storage` 候选 | 当前登录账号、本人昵称、角色归属 |
| `windows_backend.discover()` 的小型路径 INI 读取 | 增补自定义 `xwechat_files` 基础位置 | INI 路径不是已验证的登录身份或昵称映射 |
| `record_read()` 的私有账号资料索引 | 同一工作区曾经明确记录的 root/owner/nickname 提示，不依赖当时的来源/目标角色 | 历史昵称不代表本次验证成功，不能证明当前登录的账号 |
| `main_processes()` 和 `windows_capture.Process` | 所选程序的唯一主进程、程序路径/签名/SID检查 | 多个数据目录不是多个主进程，不要求目录与文件占用PID相交 |
| 全部必要库密钥/HMAC/完整性及 `account_nickname()` | 所选真实目录通过验证后，按精确内部 username 查询唯一的本人联系人及昵称 | 外部微信号、窗口昵称、目录编号和修改时间不能替代此证据链 |

现有取钥接口先接收已选目录，WCDB候选解析没有返回可验证的登录账号和目录绑定。没有现成、已验证的登录缓存解析契约可以补齐这一步。**本轮没有实现无目录首次自动识别，也没有对多个目录轮流取钥。** 没有验证过的缓存昵称不作为身份依据。

## 历史昵称索引

账号发现只读当前工作区明确索引的元数据：`account-material.json`、版本/标识匹配的 `tasks/<任务标识>/task.json`，以及兼容的 `settings.json`。不扫描其他实验目录、不读取索引中指向的密钥文件，也不查询聊天内容。

同一目录的提示优先使用当前账号资料索引，其次显式任务索引，最后旧角色设置。账号内部身份须与该目录候选一致；同一优先级出现不同昵称时列为“历史昵称不一致”，不按任务时间挑一个。没有owner的旧设置只保留其精确路径的昵称提示，仍不构成本次身份验证。

- 历史列表显示“昵称 · 上次识别”；同昵称的不同目录不合并，标签附完整路径，悬停和账号详情也提供路径。
- 丢失的旧路径保留为失效提示，不重绑定到另一个同名账号或新目录。
- `complete`只表示必要文件和已知分片清单就绪，不表示密码学验证或本人身份已通过；发现项的`verified`始终为false。
- 新会话不预填A/B，只有一个目录也不自动选择。刷新更新提示，但保留用户的选择，不写回旧设置；若所选目录已缺库，则取消该侧本次核验，保留路径与另一侧成果。
- 手动选择只规范化明确层级：`db_storage`本身；它的`message`子目录返回父级；单个账号目录中直接存在的`db_storage`。不递归搜索和挑选多账号基础目录。缺库和未知分片仍明确报告。

## 验证与待实机验收

合成测试覆盖资料索引与旧角色独立、显式任务与未索引资料隔离、同名、多目录、昵称冲突、旧路径失效、缺库、层级规范化、刷新不写设置、WPF两侧独立选择和三种昵称状态。程序签名/路径/SID、唯一主进程、全部必要库HMAC/完整性与本人身份确认不变；媒体、应用和撤回实现不在本轮范围。

仍需在不同Windows文档重定向/自定义存储位置、实际微信版本及真实新账号上，由本人验证目录提示、昵称一致性和缺库提示。源码测试不证明首次账号自动映射可用，也不证明可识别所有历史登录账号。
