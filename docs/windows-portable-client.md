## 本地测试包如何使用

后续普通模式修复包输出至 `dist/windows-ordinary-media-accounts-20261109/`：取消账号占用PID对应门槛，新会话自行选择来源与目标，任意顺序读取；缺媒体条件跳过本体并计数。包内仍为同一腾讯原版4.2.0.13载荷。**尚未实现Windows用户/系统隔离，也未实际启动微信验收。** 下述早期测试包目录仅保留追溯。

本地开发产物目录为 `dist/windows-next-portable-wechat-4.2.0.13-20261109/`。这是未发布的独立便携包，不替换公开 0.5.6 安装包，不自动迁移旧设置。

1. 完整解压便携 ZIP 到新目录，保留 `runtime/`、`app/`、`wechat/`、配置与清单。
2. 打开 `ChatRescue.exe`，界面标记“未发布开发版 · 包内固定微信”；准备页程序路径固定，不受旧设置中的本机微信路径替换。
3. 准备软件时验证整个程序清单及主程序的版本、腾讯签名；启动与读取也绑定这份程序。文件增加、缺失、哈希变化或版本漂移时停止，不静默改用本机其他版本。
4. 之后由本人按 [零基础教程](windows-beginner-guide.md) 完成先 A 核验退出、再 B 登录导入。**本轮只验证了离线包，不能承诺第一个登录或导入步骤已经成功。**

实际主程序位于 `wechat/Weixin.exe`。单独复制这个 EXE 会遗漏依赖；免安装表示无需运行系统安装器，不表示不需要手机确认或数据目录核对。

## 数据隔离和验收边界

当前 A、B 共用一份固定程序，顺序登录，不是两套自动隔离的微信环境。共用程序不等于共用账号数据库；真正必须分别核对的是 A/B 的账号数据目录和密钥。仅把程序复制成 A、B 两个文件夹不能证明数据隔离。

**程序目录独立，不代表账号数据目录独立。** 没有经过验证的便携参数时，不改注册表、用户目录或环境变量去伪造隔离。仍按实际微信配置、本人身份和 DB/WAL/SHM 占用核对账号；原版微信运行时禁止并行打开。

本地包内恢复工具后台环境检查、固定程序文件哈希与签名核验，和微信自身运行是不同检查。尚待单独验收：免安装启动、登录/切换账号、手机 B 导入、实际数据位置、取钥、真实客户端恢复显示、媒体播放与手机迁移。

## 记录和备份保存在哪里

- 微信实际记录仍在本人微信配置的数据位置，通常结构为 `xwechat_files/<账号目录>/db_storage`，媒体位于该账号目录下；以工具“账号详情”显示的实际路径为准，不固定为某个盘符。
- 恢复应用写入 A 已核对的实际账号目录，不把工具便携目录当作聊天库；工具不向 B 应用写入。
- 工具默认私有工作目录为 `%LOCALAPPDATA%\ChatRescue\Desktop`。本次 A 数据库原件在 `jobs/<任务ID>/sync/A-plan/originals/`，附件原件在同级 `original-assets/`，B 原始快照在 `jobs/<任务ID>/sync/B-plain/_encrypted_snapshot/`。
- 如果已指定独立工作目录，以上路径改以该目录为起点。便携包中的程序文件与这些私有资料分离，不要把私有工作目录作为程序包发给别人。

## 维护者打包接口

正式构建新增 `--wechat-directory <完整官方载荷目录>` 和 `--wechat-manifest <已审核清单>`，必须同时提供；不提供时保留原先使用本机微信的包。清单版本为 1，包含 `executable`、精确 `file_version`、官方 `source_url` 和逐文件 `files` SHA-256 映射。

构建器只复制清单内已审核的程序文件并复核副本，配置使用相对路径并固定清单哈希。正式发布前仍要求干净、已提交的源码；当前新增源码和文档尚未提交，不能把本地开发包标为正式发布。
