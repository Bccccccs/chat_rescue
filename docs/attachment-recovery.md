# 图片、视频和文件附件实验模式（0.5.0）

这是本地开发版功能，尚未发布到下载页。已实现离线打包、方向/路径转换、候选、应用与回撤；尚未写入真实微信库，微信内大图查看、视频完整播放、文件打开及手机迁移需分别验收。

## 支持范围

Mac Apple Silicon / 微信4.1.13，双方授权单聊；实际恢复写入仍限单个message_0.db。Mac只读检查可枚举全部普通分片，检测到多分片会停止恢复计划；不会悄悄只处理0号库。Windows附件、群聊、表情/位置/链接等其他类型、未知媒体格式仍不支持。

启用后，基础类型外增加图片3、视频43，文件49子类型6同时携带附件本体；语音34使用独立语音开关，两者可以组合。仅接受已观察方向结构、status=3和upload_status=0；不把未知消息状态套成文本状态。图片/视频资源需按会话、发送者、真实消息编号、时间及本地编号核对，data_index必须是文本0。

- 图片：复制本地可核对的非缩略图片内容及已下载相关资源，不承诺源端未下载的高清原图。只有缩略图时停止。支持保守校验的PNG、JPEG、GIF、WebP、WXGF/HEIF等容器及旧XOR、DAT V1/V2封装；不转PNG、不取首帧、不重采样。格式头/CRC/容器检查不能代替真实客户端解码。
- DAT V2：从本账号本地app_data元数据文件名派生候选，源图解密校验后仅将原图载荷放入私人bundle；目标账号必须有可验证的已有加密图样本，再按目标密钥重加密并解密读回核对。目标证据样本纳入变化检查。密钥不写bundle、日志或公开文档。没有可验证来源时停止，不能直接复制另一账号密文或猜测密钥。
- DAT V1：AES固定部分按已适配布局处理；存在XOR尾部时，需要目标已有可核验V1样本。无法区分的尾部或未知布局停止。
- 视频：保留本地MP4原文件及匹配到的已下载相关资源，不转码、不抽帧；缺视频而只有封面时停止。容器头检查不证明实际解码或完整播放。
- 文件：按消息XML的标题、总大小和MD5核对msg/file月份目录的准确文件；名称改变、内容不符或缺失时停止。工具只复制，不打开或执行文档/程序。

单文件最多256MiB，单bundle附件总量最多2GiB。月份目录目前按Asia/Shanghai对应消息时间处理；不同目录规则需另行适配。已声明下载完成的资源若缺文件，不按完整成功处理。其他未下载变体不自动从服务器获取。

## 桌面操作

沿用五步向导核对A/B。读取页勾选“同时恢复图片、视频和文件附件（实验功能）”；需要语音时同时勾选原语音开关，然后重新读取、生成预览。没有语音时附件模式仍使用四个基础库；启用语音才增加媒体库及对应密钥验证。图片DAT密钥来源与SQLCipher数据库密钥不同，数据库取钥成功不代表所有图片均可解密。

预览分别显示图片、视频、文件新增及已有消息补附件数量，语音单独统计。遇到缺失、冲突或未知结构时停止，并保留双方原记录；只补文件的计划可以没有数据库候选，但仍检查全部数据库依赖。用户确认具体计划后再应用。

应用后请在原版微信核对双方头像、方向、时间和已有消息，点击大图、播放完整视频和语音、打开文件检查内容；重启后复查。需要手机时由本人完成微信官方迁移并再次分项验收，电脑结果不能代替手机结果。

## CLI

沿用[SOP](recovery-sop.md)已核对的本人身份、路径和双方授权，在export-db、save-chat、plan-restore或plan-sync的原参数末尾加`--include-attachments`。需要语音时再加`--include-voice`；apply/apply-sync/undo-sync从计划读取能力，不需要追加开关。附件开关不要求额外扫描微信进程取图片密钥。

```sh
python3.14 -m chat_rescue export-db \
  --db-root "$SOURCE_DB" --keys "$WORK/source-keys.json" \
  --output "$WORK/source-plain" --include-attachments
python3.14 -m chat_rescue save-chat \
  --plain-root "$WORK/source-plain" --owner "$OWNER_B" --peer "$OWNER_A" \
  --output "$WORK/chat" --include-attachments
python3.14 -m chat_rescue plan-restore \
  --source "$WORK/chat" --target-db-root "$TARGET_DB" \
  --target-keys "$WORK/target-keys.json" --target-owner "$OWNER_A" \
  --output "$WORK/restore-plan" --include-attachments
```

所有变量均指本人已核对的本机值；工作目录须在仓库和微信账号目录之外。源附件在save-chat阶段从导出报告绑定的账号根目录读取，仅打包所选单聊；不要把整个账号目录交给对方。bundle含原始私密图片、视频和文件，压缩不是加密。

旧版拒绝v3。附件模式不能把不含附件清单的旧bundle当完整附件恢复，需要重新导出；纯基础文本可继续按原能力处理。v3组合能力与本次显式开关必须一致。

## 缺失、冲突与重复

源端完整、目标缺消息时，新增消息和所需文件/资源；目标已有相同消息但缺文件时只补本体或所需资源，不重复插入。相同共享缓存路径只写一次。目标已有相同内容则保留；不同非空文件、同名不同内容、MD5或关联冲突均停止，不重命名猜测或覆盖。

单向导出遇到缺主要内容时停止；双向私人中间bundle可记录缺失，从另一侧应用前的不可变原件补齐。双方都缺失不能恢复，不能以本轮刚写入的一侧作新来源。只有缩略图、封面或空文件不算完整媒体。

## 安全应用、回撤与中断

v3计划的数据库路径仍有固定白名单，附件只允许该账号msg/attach/会话哈希/月份/Img、msg/video/月份及msg/file/月份内的安全文件名。图片候选目录必须对应目标单聊；拒绝路径穿越、绝对路径、符号链接、重复清单、篡改和多义匹配。

附件源/目标文件、已存在或不存在状态及DAT目标证据图都参与双方应用前检查；候选先在私有计划目录生成，不直接修改真实目录。应用先保留所有数据库与附件协调原件，暂存并校验，再替换数据库和附件。每个数据库/文件均记录持久化意图与完成日志，不宣称多文件整体原子替换。

正常写入异常会尝试一起回撤；rollback_failed明确列出失败路径。单向originals保存数据库及sidecar，original-assets保存已有附件依赖；新建文件的原状态记录为不存在。只有apply-started而没有明确applied或rollback结果时保持微信退出，保留数据库、附件、候选和日志，不重跑、不只回填一个库或一个文件。需要人工处理时结合整套回执核对。

完整应用后，undo-sync先检查数据库和附件是否产生新变化；变动时拒绝覆盖。撤回只还原本次修改的附件，保留原有文件和其他会话。撤回本身失败会尝试修复到撤回前状态并记录结果；中断或修复失败需要人工保留现场处理。单向没有独立自动undo命令。
