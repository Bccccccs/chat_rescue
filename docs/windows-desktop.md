# Windows 桌面向导（0.6.0 三步 / 历史五步）

0.6.0 整合：当前源码主导航已合并为三个步骤，账号只在第一步选择和读取；第二步统一检查并预览，第三步应用与结果。包不含微信且不要求重装，使用本机官方程序。新增任务导出/载入和本机进度入口；下文五步为公开0.5.6历史说明。最新按钮与接续要求见 [三步教程](windows-beginner-guide.md)。

第一次使用请先看 [Windows 零基础操作教程](windows-beginner-guide.md)，按按钮完成安装、A/B 登录、昵称核验、预览与结果检查。

## 0.6.0 普通模式账号选择

目标和来源是本次可选择的账号角色，不是固定微信进程。当前源码取消账号目录与文件占用PID交集门槛：运行中的读取使用所选腾讯程序唯一主进程，仍核验程序路径、Windows用户SID、账号目录、全部所需库密钥/HMAC/完整性与本人昵称。已有密钥且微信退出时继续支持离线核验。

两边可任意顺序读取。界面明确“目标账号 · 要恢复到这里”和“来源账号 · 提供聊天记录”；没有互换按钮。每次新会话从空白账号选择开始，可显式“载入上次账号选择”或已有任务；仅打开/刷新不会覆盖历史设置。来源记录完整性确认与具体应用确认仍保留，来源和目标必须是不同真实账号。

用户选择先完成普通模式修复，不创建Windows用户或沙盒。**微信本身仍使用当前Windows用户的环境，尚未隔离登录缓存；免安装副本不等于全新用户环境。** 下文先A后B及占用进程对应说明为已发布0.5.6历史行为，不作为0.6.0 要求。

0.5.6 同时提供默认关闭的 Windows 媒体本体实验开关：原语音及图片/视频/文件可独立启用，语音须补齐媒体库密钥，附件须本地文件和可验证目标证据。媒体仅有合成离线与加密应用/撤回验证，真实 Windows 结构、打开/播放与手机迁移未验收；缺证据停止。详见 [Windows 媒体实验](windows-media.md)。

0.5.6 修复原生辅助表兼容误报：只对已观察的 MessageGroupTimeInfo 可选布局、未读列表与 biz_info 的字段顺序差异按明确结构核验；会话主表与未知结构检查保留。A 的数据与物理字段顺序保持，分片分配规则沿用 0.5.5。见 [0.5.6 说明](releases/v0.5.6.md)。

0.5.5 新增 A/B 必需结构与候选索引核对；通过未改动会话的独立原生范围证据识别分片，按时间分配源消息，证据不足即停止。仅在候选中清理所选会话失效的搜索范围，预览显示每片数量与日期；真实微信显示、搜索重建与手机迁移仍需本人验收。见 [0.5.5 说明](releases/v0.5.5.md)。

0.5.4 修正当前 Windows 单聊的 packed 字段含义：字段 1 为发送者、字段 2 为接收者，均按各消息分片的 Name2Id 校验并映射到目标分片，不能当固定 3/2 方向值。4.2.0.13 回执导出使用独立 participant-ids 配置；本版 B→A 模式可复用已验证的旧 Windows 回执，逐条执行发送/接收双方身份检查，不改旧报告或伪造版本。已有的 0.5.3 失败任务保留，重新生成预览。真实证据为所提供账号对的文本元数据配对，不能外推客户端、手机或所有非文本已验收。

0.5.4 Windows 桌面版只生成 **B → A 单会话替换**：B 是唯一聊天来源，A 原会话在候选副本中移除后重建，其他会话和 A 草稿保留，B 不写入。系统类型 10000、10002 暂不导入并按类型计数；不把其他未知方向或发送者错误当作中立条目忽略。未知普通方向显示实际值、预期值和类型并停止。替换会移除 A 独有的此会话消息，必须先核对具体移除/导入数量与原件，再确认应用；不要人工删除真实聊天。CLI 原有双向模式保留，不能将其说明当作本版桌面默认行为。

Windows 本机开发版使用 WPF 原生窗口，沿用 Mac 版的侧栏、蓝色操作按钮、账号卡片和五步顺序。窗口操作由本地 stdin/stdout JSON 桥接到现有 Python 恢复引擎，不启动网络服务。真实恢复范围仍以 [Windows 说明](windows.md) 和 [实测证据](evidence-and-support.md) 为准。

本地请求使用 JSON Unicode 转义，返回值使用 UTF-8，避免中文 Windows 的 GBK 默认管道编码破坏昵称、中文路径或表情。旧构建若出现 `utf-8 codec can't decode byte 0xb0`，重新构建并打开新版后再载入任务；不需要删除聊天或修改密钥。

## 构建并打开

普通使用者请优先下载 [0.6.0 安装包](https://github.com/Bccccccs/chat_rescue/releases/tag/v0.6.0)，已包含 Python、SQLCipher 和后端，不需要源码或下面的构建环境。[安装与跨电脑部署](windows-deployment.md) 介绍依赖、便携包和卸载后的资料保留。以下 `build.ps1` 仅用于开发者的本机构建。

需要 Windows x64、系统 .NET Framework 4.x（含 WPF / C# 编译器）、Python 3.14 和匹配架构的 SQLCipher 4 DLL。无需安装 .NET SDK。替换下面路径，在仓库根目录的 PowerShell 执行：

```powershell
.\desktop\windows\build.ps1 -Python 'C:\你的Python目录\python.exe' -SqlCipher 'D:\你的依赖\sqlcipher.dll' -Weixin 'C:\你的微信目录\Weixin.exe'
.\dist\windows\ChatRescue.exe
```

输出 `dist/windows/ChatRescue.exe` 和本机 `backend-config.json`。配置包含 Python、DLL 与仓库路径，不包含密钥值。此构建依赖这些路径继续存在，不是可拷贝到任意电脑的独立安装包；源码与构建产物分开保存，dist 不提交 Git。已处理的账号路径与昵称保存在私有 `ChatRescue/Desktop/settings.json`，只保存密钥文件路径，不保存密钥值或应用确认。应用关闭后，已有任务与回执仍保留；通过历史任务或载入已有账号任务继续，不会自动重做应用。

模拟首次部署时，可在构建命令增加 `-Workspace 'C:\你的私有目录\FirstRun\Desktop'`，指定一个新的绝对工作目录。此设置写入本机构建配置，重新打开仍使用该目录；后端也接受同用途的 `CHAT_RESCUE_WORKSPACE`。新的工作目录从空白账号设置开始，昵称标签只来自当前工作目录的显式保存设置，不扫描旧实验回执来补全。安装的微信及其数据目录仍通过系统配置正常发现；这种首次使用测试不重装依赖，也不清除微信记录、旧项目原件或应用回执。

## 历史五步（0.5.6）

A 是希望补回记录的目标账号，B 是仍保留记录的源账号。首次使用时两张账号卡片不预填昵称或密钥；系统发现的账号目录显示为待识别目录。登录本次账号后，选择其实际目录并核对授权，再点击该角色的“读取账号”，验证成功才显示本人昵称。不能只按目录序号判断账号；选错目录或无法唯一对应进程时停止读取。完全首次使用的逐步人工验收仍在进行。

1. **准备软件**：自动检查环境，再验证所选原版微信版本、架构与腾讯签名。打开向导只做环境和目录检查，不自动启动微信或取钥。
2. **登录两个账号**：每次只打开一个原版微信。先点击“打开微信 A”，本人登录目标账号并点击“读取账号 A”；核验通过后正常退出，再打开并登录 B。**现在从手机 B 将与 A 的聊天导入电脑微信 B**，等待导入完成；如果电脑 B 已有完整记录，可直接核对。请在电脑 B 检查目标单聊、内容和时间范围，再勾选“已完成导入或确认电脑 B 已有完整记录”。确认前不能读取 B 或生成预览；A 阶段和恢复结果页不提示再次导入。已有微信运行时拒绝再次启动，B 按钮在本次 A 核验前禁用。若登录页记住另一账号，需本人切换。历史昵称标为“上次读取”，不能替代本次确认。
3. **读取双方聊天**：本人核对账号与授权后，按 A → B 顺序读取，B 必须先完成上一项的导入/完整性人工确认。微信运行时查询全部消息分片及辅助库的占用进程，唯一匹配才取钥；已有密钥且微信已退出时，重新验证全部分片及本人昵称，无需重复登录。重新打开向导、更换账号/密钥或重新登录时清除导入确认，不保存核验标志。两边完成并退出微信后才生成预览，保存所有分片的 DB/WAL/SHM 原件。未完成本次两侧核验、身份确认或 B 记录确认时预览禁用。空白消息库未初始化时停止。
4. **确认补齐预览**：显示双方昵称、新增/去重数量和任务目录。本人确认复选框，再确认含昵称、条数与原件位置的具体应用摘要，才调用协调应用。计划哈希改变、已有应用或中断回执时拒绝重复执行。载入隔离模拟报告只显示实验数量，不提供应用真实账号的按钮。
5. **检查恢复结果**：数据库回执、本人电脑显示确认、手机未验收分别展示。只有整体应用成功才能记录本人电脑验收。撤回需再次确认，且仍由原有引擎核验双方后续变化，保留撤回前原件。不能用电脑确认代替手机确认。

## 本机构建验证与限制

- 原生程序已编译并实际打开，准备、登录、读取、无计划预览、隔离报告、未应用结果页面经过 UI 检查；环境与原版签名检查成功。
- 桌面桥接新增保护测试覆盖：确认前不应用、计划变化拒绝、部分/中断/已完成任务不可重复、进程绑定歧义拒绝、空白库错误转换、隔离报告不返回应用计划或密钥、电脑验收及撤回条件。
- 本次 UI 开发没有再次启动真实微信、取钥或修改真实聊天库；此前实机取钥和隔离恢复证据单独记录。
- 完全空白目标缺少 `Name2Id` 的初始化仍未适配。界面完成不代表此恢复场景已支持，也不代表真实双账号 GUI 应用、微信显示或手机迁移已验收。安装版已在本机隔离目录验证安装、内置运行时启动与卸载后资料保留，尚未完成干净虚拟机的完整验收。
