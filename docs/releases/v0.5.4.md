# 0.5.4 Windows 单聊参与者编号修复实验版

保留 0.5.3 的 B→A 单会话替换：B 为唯一聊天来源，A 原会话只在候选副本中清理，B 不应用写入。已知系统类型 10000/10002 暂不导入并计数，其他未知身份/结构继续拒绝。

## 修复原因与行为

脱敏诊断中，A 文本 15250 条、B 文本 39585 条。每个分组均显示 packed 字段 1 匹配发送者，字段 2 在本分片 Name2Id 中映射到另一方。发送与接收均可出现 1/2，15/68 是本地编号而非独立方向标记。原来的固定 3/2 检查不适用于这批数据。

- 新增 `windows-4.2.0.13-participant-ids` 配置，发送者和接收者都从每条消息所属分片的 Name2Id 验证；源编号先解析为绝对身份，再映射到 A 的目标分片。既不把 15 硬改为 3，也不放宽身份冲突检查。
- bundle 保存分片参与者映射，读取时重新校验字段 1、字段 2 与两个明确账号的关系；未知接收者、伪造映射或冲突拒绝，其他 packed 元数据保持原样。
- B→A 模式可复用已绑定账号且全部库验证通过的 Windows 回执，生成新候选时逐条验证参与者结构。4.2.0.13 常规导出会选择新配置；旧 bundle/旧配置不被静默修改。
- 文本按 A 视角设置发送/接收状态；非文本状态按原行为保留。真实编号、正文、时间、稀疏映射、资源/会话重建、原件、应用前哈希和失败回撤保护保留。

## 升级

关闭旧程序，安装 0.5.4 或完整解压新版便携包到新目录。确认左下角为 **0.5.4**，复用各自已有密钥和配套回执，重新核验账号并生成新的 B→A 替换预览，无需为此重复取钥或删除聊天。保留全部失败任务和原件，不修改旧回执、版本号或旧计划。

预览显示 A 将移除、从 B 导入和暂不导入的数量。本人确认具体计划后才替换真实会话；替换会移除 A 独有的该会话消息，完整原件保留，其他会话和 A 草稿保留。

## 验证边界

实机依据为这对账号提供的文本诊断汇总；非文本参与者转换有结构检查和合成测试，尚无全部类型客户端验收。Windows 不搬运附件本体，不保证语音播放或图片/视频/文件打开。真实 GUI 恢复显示与独立手机迁移仍需本人验收。Windows x64 未签名实验预发布，Mac 下载保持 0.5.0；本次开发和打包不启动微信或修改真实聊天库。
