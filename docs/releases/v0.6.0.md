## 本轮做了什么

| 问题 | 0.6.0 的处理 |
| --- | --- |
| 登录、读取拆成重复页面 | 合并为“准备并读取账号 → 检查恢复预览 → 应用与结果”三步 |
| wxid 目录难判断、昵称显示不一致 | 统一工作区明确索引的历史账号资料；昵称、下拉框、详情同步，显示同名路径、旧路径及缺库；新增“去哪里找？” |
| A/B 与进程强绑定、多个历史目录误判多个进程 | 来源和目标由本人选择，可任意顺序读取；不以目录数量判断主进程，不再要求目录与文件占用 PID 相交，仍只接受所选签名程序的唯一主进程 |
| 旧密钥回执挡住新库清单 | 明确候选重新逐库核验，全部 HMAC、完整性与本人身份通过后生成新回执；旧回执不改写，缺钥明确列名 |
| 已解析带盐候选却没有执行 HMAC | 嵌入盐只作优先顺序；已解析的明确密钥候选须接受实际首页 HMAC 核验，错误候选仍拒绝；保留 SID、路径和签名保护 |
| 多媒体库或常见格式遇阻 | 枚举全部已有规范 media_N.db；支持明确音频和图片/视频容器，不猜目标库、不自动建片；常见 WCDB 元数据备份后缀不误报为未知 sidecar |
| 一个附件状态或缺媒体导致全程停止 | 对未适配图片/视频/文件状态、格式或缺本地媒体及可验证图片条件，跳过本体、保留消息和原状态，按原因计数；跨消息分片汇总状态与数量 |
| 换电脑后找不到任务 | 当前任务可导出/载入；只转移明确关联资料，校验相对清单和哈希。旧候选/应用/中断回执是只读历史，桌面和底层 CLI 都禁止直接应用或撤回 |

Windows 桌面仍只做 **B → A 单会话替换**：B 提供保留记录，A 的这段单聊在候选中按 B 重建，A 其他会话与草稿保留，B 不应用写入。A 独有的本段消息可能被移除，必须核对具体预览，确认后才应用；不要先手动删除聊天。

## 媒体可以做到哪一步

语音和附件本体两个开关默认关闭。语音已加入明确的 SILK、PCM WAV、AMR-NB 载荷识别；视频加入 MP4/MOV/M4V/AVI/MKV/WebM/3GP/3G2 等明确容器检查；图片包含常见格式和严格限定的 BMP、TIFF 等规则。容器识别不等于微信解码与播放验收，精确范围见 [媒体说明](../windows-media.md)。

缺库、缺本地音频/附件、图片解密不可验证或目标重加密证据不足时跳过相应本体，预览解释原因；保留消息不等于本体恢复成功。**已存在库的 HMAC/完整性、未知语音结构、身份/方向/关联冲突、路径及哈希异常仍停止**，不能将这些保护当成未知附件状态吞掉。

## 升级与接续

1. 下载新包，完整解压或安装；无需重装微信。
2. 新会话明确选择来源和目标；历史昵称只作提示，每次重新核验。语音开关改变后双方须重新验证媒体密钥。
3. **旧媒体预览全部重新生成**：v5 新增明确能力，旧客户端与旧能力清单不可混用。
4. 同一电脑用“继续本机任务”；同一授权操作者换电脑用“导出接续任务 / 载入接续任务”。接续资料可能包含密钥、聊天和整库原件，须私密保管。
5. 新电脑需要双方真实数据库可访问，重新定位、核验并生成新预览。迁入旧应用/中断回执保持历史状态，不能用旧绝对路径重复应用；已应用或中断时显式新建任务。

## 证据与尚未解决的限制

- 账号发现、历史昵称、多目录/同昵称/旧路径、刷新与角色独立均以合成资料回归。读取没有绕过所选程序路径/签名/SID、全部必要库 HMAC/完整性与本人身份核验。
- 首次登录账号到内部身份、实际 db_storage 和本人昵称的自动对应，**现有证据不足以普遍可靠实现**。不按修改时间、编号、对外微信号或昵称相似度猜，不盲目逐目录取钥。详见 [账号发现调查](../windows-account-discovery.md)。
- 既有实机取钥/导出依据主要是微信 4.2.0.12，另有特定 4.2.0.13 账号对的文本方向证据；真实 4.2.0.50 取钥仍未验收，版本准入不是成功保证。
- 未适配的真实语音库表结构仍可能阻止语音模式；Windows DAT V2 图片参数自动取得能力尚不完整，无可验证参数时跳过。
- 普通模式共享当前 Windows 用户环境，微信可能记住其他账号；没有实现宿主登录缓存隔离。
- 合成加密库候选、应用、失败回撤、撤回与传输保护检查，不能替代真实客户端的完整上翻、搜索、图片打开、语音/视频播放及手机迁移验收。
- 新电脑的干净安装、实际账号重新核验与完整接续尚需现场验收。本版维护没有启动微信、实际取钥或读写真实聊天库。

公开图示均为通用重绘，不包含用户提供的私人聊天截图、昵称、账号标识或本机路径。测试与发布构建记录见 [验证记录](../testing.md)。
