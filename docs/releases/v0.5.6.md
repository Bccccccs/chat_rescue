## 问题原因与修复

修复 0.5.5 在正常分片上误报“B 各分片辅助表结构不一致”。已有报告确认会话主表一致；差异为原生可选表出现位置以及两个只读辅助表的物理字段顺序。

- `MessageGroupTimeInfo` 可只存在于部分分片；出现时必须符合已观察的五个字段、类型和复合索引，不按表名无条件放行。A 已有内容原样保留。
- 对 `SessionUnreadListTable_1` 与 `biz_info` 的已知原生布局，按字段名、声明类型、主键和逻辑索引核对，允许列的物理顺序不同。A 保持自己的字段顺序与数据，不复制 B 的未读或公众号状态。
- 消息主表继续严格检查。未知列、类型、默认值、约束、索引方向、排序规则、外键或触发器仍拒绝，不把所有辅助表差异都当作兼容。
- 遇到新的结构差异，生成阶段自动在私有任务目录保存 `schema-diff.json` 并显示位置；报告只有结构元数据，字符串常量已隐藏，不包含正文、密钥或账号标识。

保留 0.5.5 的 B→A 单聊替换、原生独立证据分片分配、逐片收发身份与本地编号映射、候选范围清理、哈希/备份/失败回撤。每片至少两个独立未改动会话才能识别分片，歧义停止。系统类型 10000/10002 暂不导入并计数，B 只读，A 其他会话与草稿保留。

此前“JSON 有早期记录，A 客户端只能看到较晚月份”的审计显示：合格消息的编号与时间已完整进入候选和当前 A，没有发现按条数或月份截断；候选将该会话集中到单片，原生搜索范围仍指向旧分布。0.5.5 已改为按经独立证据核对的 A 原生范围分片，0.5.6 保留该修正。**这项修正能否解决真实微信的连续上翻、日期定位与搜索可见性，仍须用新版具体候选验收。** 不能仅凭总条数一致宣布显示完整；详见 [排查证据](../evidence-and-support.md)。

## 可选 Windows 媒体本体实验

同版加入原语音、图片、视频和文件本体候选，两个开关默认关闭，可独立开启。语音需双方全部消息分片、三个辅助库及单个已有 media_0.db 的密钥与验证；旧四库回执不能提前完成。仅接受明确的 VoiceInfo/Name2Id 字段、默认值和索引、已适配状态、data_index=0 与 SILK v3 头，额外媒体分片或未知结构停止。

附件只处理 B 已下载且严格关联的本地内容；图片跨账号加密需兼容本地元数据与 A 可核验样本，缺文件、缺目标证据、冲突或未知格式停止。Windows 使用系统 CNG AES，不增加运行时依赖。媒体模式使用 v5 清单及明确能力，旧版拒绝；数据库和文件协调备份、暂存、应用、失败回撤与撤回，B 保持只读。

**媒体目前只有合成离线/加密测试，没有真实 Windows 媒体结构、打开、播放或手机迁移证明。** 不能承诺启用后所有格式都能打开。范围、限制与操作见 [Windows 媒体说明](../windows-media.md)。

包内增加 `run-history-audit.cmd`、`run-visibility-audit.cmd`、`run-schema-audit.cmd`，直接调用当前安装版本的诊断模块，支持媒体清单并保留进度与私有报告；历史编号/日期诊断不替代媒体播放验收。

## 升级与使用

关闭旧工具后安装新版，或完整解压便携包到新目录，确认界面为 **0.5.6**。基础模式或已有完整媒体密钥时可复用既有授权密钥与回执；启用原语音而只有普通库密钥时，须由本人核对账号、原版程序与进程，补齐媒体库密钥和全部库验证。重新核验账号并生成具体预览，核对每片日期范围、移除/导入数量及原件后，再由本人确认应用。无需人工删除聊天或修改旧报告。

验证包含已知结构差异复现、未知约束/索引拒绝、原数据保留、多分片混合媒体应用/撤回、源文件和媒体 WAL 变化拦截、附件中断/故障日志与回撤，以及完整回归和包内运行时检查。真实微信的最早日期、连续上翻、日期定位、搜索重建、媒体打开与手机迁移仍需独立验收；本版不声明已经完成这些验收。Mac 下载保持 0.5.0。

版本入口允许微信 **4.2.x.x x64**，不再仅按 4.2.0.12 放行；全部分片密钥、回执绑定、身份、结构、完整性与冲突检查仍执行。4.2.0.13 的参与者字段按每片 Name2Id 映射，不能把 1/2/15/68 等本地编号直接当固定方向值。

## 报告和本机查看文件

默认工作目录是 `%LOCALAPPDATA%\ChatRescue\Desktop`；更改过工作目录时以工具显示位置为准。将目录路径粘贴到资源管理器地址栏打开，路径本身不是命令。每个诊断工具也会打印本次输出目录。

| 文件 | 默认位置及用途 |
| --- | --- |
| 本次替换预览与应用回执 | `jobs\<任务ID>\sync\A-plan\preview.json`、`applied.json`、`apply-journal.jsonl`；原件为同目录 `originals\` |
| 自动结构差异报告 | `jobs\<任务ID>\sync\schema-diff.json`，生成阶段结构失败时保存 |
| 独立结构检查 | `schema-audit-<随机ID>\schema-diff.json` |
| 历史检查汇总与进度 | `history-audit-<随机ID>\history-audit.json`、`progress.log` |
| 恢复候选中 A 视角的对话 JSON | 历史检查目录内 `A-candidate-chat\conversation.json` |
| 检查时实际 A 库的对话 JSON | 历史检查目录内 `A-current-chat\conversation.json`；当前 A 快照成功后生成 |
| 分片与客户端可见性摘要 | `visibility-audit-<随机ID>\client-visibility.json` |

`conversation.json` 含正文，仅供本机查看，诊断 JSON 不能作为恢复 bundle 使用。可提供汇总报告定位问题，不公开密钥、数据库、正文 JSON 或整个工作目录。当前 A 快照要求微信正常退出；检查失败时先看已保存的汇总报告与进度，不重复应用旧任务。
