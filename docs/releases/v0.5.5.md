# 0.5.5 Windows 分片分配与结构核对实验版

针对“源记录及 A 实际数据库均含早期消息，但微信只显示较晚日期”的问题，修正替换候选集中写入单一分片、保留失效搜索范围的行为。编号和时间完整不代表客户端显示已验收；本版仍为实验预发布。

## 新行为

- B 仍是唯一来源，A 仅替换所选单聊，其他会话及 A 草稿保留，B 不写入。系统类型 10000/10002 暂不导入并计数。
- 生成前比较字段、类型、约束、索引、外键及必需辅助库结构，生成后再次核对候选。原生按需创建的删除/历史操作表允许缺席；已有同名表结构必须一致，未知结构不自动改写。
- 多分片不按文件编号猜时间：以未改动会话的原生 FtsRange 与实际表位置交叉核对，每片至少两个独立会话。时间标识与位置必须唯一，原生会话时间范围须与所得顺序相符；不足即拒绝生成。
- 按核对的目标时间范围分配源消息，早于最早边界的记录落在最早现有分片。不自动创建分片，每片使用独立本地消息编号与 Name2Id 收发身份。
- 只在候选中清除所选会话失效的 FtsRange，不声称新记录已经完成全文索引。其他会话索引不改动，不删除真实搜索库；未知范围类型拒绝。
- 加密前核对完整真实消息编号集合、时间与分片位置。预览展示每片导入数量和日期、结构核对、移除/导入/暂不导入数量及原件位置。
- 清单仍为 v4，增加 `windows-verified-shard-routing` 能力，使 0.5.4 拒绝新计划。新版桌面不能应用缺少分片检查的旧预览；CLI 旧双向与旧计划撤回能力保留。

## 升级与验收

关闭旧工具，安装 0.5.5 或完整解压便携包到新目录，确认界面版本。可复用已有授权密钥及回执；正常退出微信，重新核验双方账号，确认电脑 B 的单聊时间完整，再生成新预览。不人工删除聊天或修改旧报告。

本人核对具体预览并确认后才能应用。随后由 A 在原版微信核对最早日期、连续上翻、日期定位、收发方向与新旧消息；搜索索引重建需单独确认。A 最近新增而 B 尚未保留的本会话消息会被替换移出，须核对预览并保留原件。

本次验证为合成库的分片、稀疏身份、候选、加密应用/撤回、哈希与范围清理；真实微信显示尚需独立验收，不承诺解决所有读取情况。附件本体不搬运，手机迁移未验收。Windows x64 提供安装 EXE 与便携 ZIP，Mac 下载保持 0.5.0。
