# 桌面顺序登录改动交接（2026-11-03）

## 范围与接口

- 当前源码的启动与准备入口只打开 A；A 人工确认后才打开 B。登录页只展示当前账号及操作，不再并排提供两个启动入口。
- `desktop/LoginFlow.swift` 管理本次会话的顺序、启动成功记录、人工身份确认和 B 电脑旧聊天确认；不保存为持久化登录凭证。SwiftUI Model 在成功启动回执后记录打开，确认后推进。高级账号编辑重新从 A 检查。
- 未完成检查禁止读取，预览及结果页按实际产物开放；首次准备结束留在权限页。结果页分开提供 A、B 启动按钮。
- 底层启动 API 仍接受 slots 数组，桌面 Model 仅发起单账号启动。取钥、备份、候选和应用行为保持现有实现。昵称在读取时核验，勾选只表示本人确认。
- 构建需同时编译 LoginFlow.swift 与 ChatRescue.swift。当前下载的 0.3.5 发布包不含此次源码修改。
